# Kvest — заметки проекта

Текстовый квест о зомби-апокалипсисе на севере Германии для двух игроков: A — он (Android),
B — его девушка (iPhone). Владелец общается по-русски, пишет с телефона (Remote Control), shell-команд
ему не давать. Он тоже ИГРОК: в чате сюжет не пересказывать вовсе (см. правила ниже).

Перед работой прочитать: `docs/ARCHITECTURE.md` (архитектура, §14 — этапы и статус),
`docs/hidden/STORY_DESIGN.md` (дизайн сюжета), `docs/hidden/WORLD_BIBLE.md` (законы мира).
Новые главы пишутся по `docs/hidden/CHAPTER_GUIDE.md` (процесс, устройство, два телефона, чек-лист ошибок) и
`docs/hidden/WRITING_GUIDE.md` (голос и стиль). `AGENTS.md` — те же правила для агента ChatGPT/Codex: владелец переносит
поддержку туда; главы, написанные там, приходят PR-ом — проверить на отличия от стиля и устройства глав 1–2 (даже мелкие),
прогнать тесты и браузер, исправить, слить.
Исходные ТЗ владельца: основное (двое, офлайн, КТ, совместные решения, реализм, нет брони) и дополнение
«дни 1–4» (темп: бегство → организация → ресурсы → жизнь на базе, база не гарантирована, игрок не лидер
автоматически, не каждая встреча — бой). Их суть перенесена в эти документы.

## Решения владельца (не менять без него)

- У персонажа A **нет родителей** в истории. Родственников обоих не вводить без просьбы.
- Персонажи **не появляются в истории друг у друга первое время**: звонок/SMS партнёру — не раньше
  `partnerContactAfter` (07:15, ≈5–8 решений) и в конце списка действий; в первых сценах — ни слова о партнёре.
- A: 184 см, 88 кг, зал 3+ года, бокс в прошлом. B: 167 см, 50 кг, не сильная, немного зал. Физические
  черты не правятся при создании, остальные ±3.
- Старт: A — Buchholz i.d.N., B — WG в Hamburg-Barmbek, вт 10.11.2026 06:30.
- Сюжетных картинок нет.
- Безопасность облака владельцу не важна: токен едет в приглашении. Но токен **не класть в код** — GitHub
  отзывает токены в публичном коде.
- **Настоящая игра идёт с 30.10 (вечер): историю только дописывать.** Пара играет с 30.10 20:35, КТ 1 пройдена
  (облако: `pairs/Uwz9uRin2OZVCugy`). Начать заново нельзя: сохранения обязаны продолжаться. Не менять поведение
  действий, которые уже могли быть сыграны (иначе журнал участка воспроизведётся у партнёра иначе) — сейчас это вся
  глава 1 (оба её участка; второй пара играет прямо сейчас). Правка текстов безопасна (хэш мира не включает тексты).
  Исправление, меняющее расчёт, включать по номеру КТ (`{ cp: N }` в условиях, `s.checkpoint >= N` в движке) — только
  с участка, который ещё никто не играл. Новые события мира, планы NPC и базы главы 2 — тоже за `{ cp: 2 }`.
  `content.version` и версию движка не поднимать без крайней нужды, а если неизбежно — с миграцией сохранений.
  Страховка — `src/content/compat.test.ts` с эталонными журналами `fixtures/release-N.json`: они должны повторяться
  бит в бит; не перегенерировать, при выпуске главы добавить следующий. Перед выкладкой — проверить, что сохранение
  пары из облака повторяется текущей сборкой (`refreshSave` не меняет хэш и не обрезает участок).
- **В чате сюжет не пересказывать вовсе** — не только спойлеры: ни сцен, ни людей, ни событий, ни мест, ни вариантов
  решений, ни того, что где может случиться или как устроены развилки. Отчёт — только «написана первая/вторая часть главы N»,
  «проверки прошли». Служебное (эталоны, ветки) владельцу не объяснять — делать самому.
- **Проект — владельца.** В самой игре и в документах проекта нет следов того, кто помогал её писать («это придумал/написал
  Claude», «для нейросети» и т.п.). Подписей владельца («сделал …») тоже не добавлять. История коммитов — не важна.
- В игре нет вступлений и описаний «что это за приложение» — владелец рассказывает сам. Оставлять только
  подсказки, без которых не сыграть (как обменяться кодом, сохранить файл).

## Как работать

```bash
cd ~/immomio-project/kvest
npx tsc --noEmit && npx vitest run      # типы + тесты (линтер сюжета, случайный игрок, два телефона)
npm run e2e:quick                        # браузер: два телефона, облако (поддельный GitHub), файлы, вкладки (~7 мин)
npm run e2e                              # то же + случайные нажатия по всем экранам (+10–15 мин)
npm run build                            # PWA в dist/
git push                                 # main → автосборка и выкладка на GitHub Pages (~2 мин)
```
- Сайт: https://andrii-nehrii.github.io/Kvest/ . Remote — `git@github-kvest:…` (deploy key ~/.ssh/kvest_deploy).
- Сохранения игроков: `git fetch origin saves:refs/remotes/origin/saves`, файлы `pairs/<id>/save-A|B.json`.
  Читать, чтобы понимать их прохождение; не коммитить их в main.
- Проверка в браузере: сценарии в `scripts/e2e/` (Playwright + Chromium, сервер предпросмотра на порту 4179 поднимается
  сам). Отдельный сценарий: `node scripts/e2e/run.cjs codes cloud --seed 3`. Запускать после каждой главы и крупных правок.
  `update` дописывает в `dist/sw.js` — после прогона пересобрать.
- Новые сцены — данные в `src/content/chapterN/`; id прошлых сцен/переменных/предметов не переименовывать
  (сохранения), поднимать `content.version` только при несовместимых изменениях.
- Экономить лимит владельца: меньше лишних проверок, крупные шаги, коротко отчитываться.
- В начале сессии назвать её «Kvest NN — тема» (следующий номер после прошлой; 01 — движок, интерфейс, облако)
  и добавить тег `kvest` (инструменты set_session_title / set_session_tags) — владелец так группирует чаты.
