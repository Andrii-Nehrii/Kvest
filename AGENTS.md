# Kvest — правила для агента

Текстовый квест (TypeScript, React, Vite, PWA) о постепенном зомби-апокалипсисе на севере Германии для двух игроков:
A — он (Android), B — его девушка (iPhone). Владелец пишет по-русски, с телефона; отвечать по-русски, коротко,
без shell-команд для него. **Владелец — игрок.** Подробные заметки проекта — `CLAUDE.md` (те же правила, читать целиком).

## Абсолютные правила

1. **Никаких спойлеров владельцу.** В ответах, отчётах, описаниях PR и коммитов, которые он может увидеть, — ни сцен,
   ни людей, ни мест, ни событий, ни вариантов решений, ни развилок, ни фрагментов текста. Только «написана глава N
   (части 1–2), проверки прошли, PR #…». Описание PR — так же (подробности — в `docs/hidden/`, он туда не смотрит).
2. **Настоящая игра идёт: историю только дописывать.** Не менять поведение того, что могло быть сыграно (главы 1–2,
   движок для прошлых КТ). Всё новое — за условием `{ cp: N }`. Эталоны `src/content/fixtures/release-*.json` не трогать,
   `src/content/compat.test.ts` обязан проходить. `content.version` и версию движка не поднимать. Id прошлых сцен,
   переменных, предметов не переименовывать.
3. **В main не пушить и не сливать.** Работать в своей ветке (`chapter-N` или по задаче), открыть PR в main и оставить
   его открытым: владелец отдаёт PR на проверку, сливают после неё. Пуш в main сразу выкладывает игру игрокам.
4. **В игре и документах нет следов того, кто их писал** (ни «сгенерировано», ни имён моделей/сервисов, ни подписей владельца).
   В игре нет вступлений «что это за приложение».
5. Токены/секреты в код не класть. Сохранения игроков (ветка `saves`) читать можно, в main не коммитить.
6. Решения владельца (не менять): у A нет родителей; родственников не вводить; партнёры не появляются в истории друг
   у друга до 07:15 первого дня; физические данные персонажей; старт 10.11.2026 06:30; сюжетных картинок нет.

## Если просят «написать следующую главу»

Строго по `docs/hidden/CHAPTER_GUIDE.md` (процесс, устройство, два телефона, тесты, чек-лист) и
`docs/hidden/WRITING_GUIDE.md` (голос, стиль, образцы). Сначала план `docs/hidden/CHAPTER<N>_PLAN.md`, потом код в
`src/content/chapter<N>/`, тесты `src/content/chapter<N>.test.ts`, самопроверка по чек-листу, затем PR (не сливать).
Где остановилась история и какие флаги есть — `docs/hidden/STORY_STATE.md`; в конце дописать туда раздел о новой главе
(и `docs/ARCHITECTURE.md` §14, «Следующий шаг» в `CLAUDE.md`).

## Команды

```bash
npm ci                                  # зависимости
npx tsc --noEmit && npx vitest run      # типы + все тесты (линтер сюжета, стиль текстов, случайные пары, два телефона, совместимость)
npm run e2e:quick                       # браузер (Playwright + Chromium): два телефона, облако, файлы (~7–10 мин)
node scripts/e2e/run.cjs codes          # один сценарий: обмен кодами через все КТ
npm run build                           # PWA в dist/
```
Перед PR: всё зелёное. Если браузер недоступен в среде — сказать об этом в PR одной строкой, без сюжета.

## Где что

* `src/engine/` — движок (без React): состояние, условия, эффекты, время, тело, слияние на КТ. Менять только с `{ cp }`/
  `s.checkpoint >= N` и тестом в `src/engine/*.test.ts`.
* `src/content/` — сюжет как данные: `chapter1/`, `chapter2/`, `index.ts` (сборка), `people.ts`, `world.ts`, `items.ts`.
* `src/app/`, `src/ui/` — сессия телефона, облако, интерфейс.
* `docs/ARCHITECTURE.md` — архитектура; `docs/hidden/` — закрыто для игроков: мир, дизайн, состояние, руководства.
