# ЗАКРЫТО ДЛЯ ИГРОКОВ — глава 3: короткая памятка и экономный режим (читать ВМЕСТО полного набора документов)

Лимит владельца ограничен. Цель — качество уровня глав 1–2 **за меньшее число попыток и токенов**.

## Что писать (только нужное)

В игру играет **одна пара**. Писать заново только места, где эта пара реально может оказаться: список считает
`pairpaths.test.ts` по настоящим сохранениям (`CONTEXT.md` §4 → `transcripts/pair-paths.txt`), писать сверху вниз.
Остальные места главы 3 **не трогать** — их текущая версия остаётся запасной. После каждой КТ, пройденной парой, список
пересчитать: он сужается, и дальше пишутся только оставшиеся места и решения.

Порядок: довести `farm5.ts` и `bflat5.ts` (CHAPTER3_REVIEW4.md) → следующие места участка 5 по списку → КТ 5 для них →
участок 6 для них и т. д.

## Что читать в начале сессии (и больше ничего)

0. `docs/hidden/CONTEXT.md` (память проекта; в конце сессии — дописать журнал).
1. Этот файл и последний `CHAPTER3_REVIEW*.md`.
2. `WRITING_GUIDE.md` §1–3 и §7 (голос, образцы «было → надо»).
3. Один образец главы 2 целиком: `src/content/chapter2/day.ts` (сцены хутора) — только при первой части сессии.
4. Свой файл части. **Не открывать** старые файлы главы 3 (`morning12.ts`, `afternoon12.ts`, `morning13.ts`, `afternoon13.ts`,
   `excursions.ts`, `atmosphere.ts`) — из них только убрать сцены, которые заменяет новая часть (поиском по id).

## Проверки — только эти, пока часть не готова

* `npx tsc --noEmit`
* `KVEST_QUALITY_FILES=chapter3/<часть>.ts npx vitest run src/content/quality.test.ts` (≈1 мин)
* одна стенограмма: `KVEST_TRANSCRIPT=part KVEST_FROM=5 KVEST_TO=5 KVEST_WANT=<место> KVEST_COUNT=1 npx vitest run src/content/transcript.test.ts`
  — прочитать **один раз** целиком.

**Не запускать** по частям: полный `npx vitest run`, `npm run e2e:quick`, браузерные сценарии, матрицы — их прогоняет
проверяющий один раз перед слиянием. Не писать длинных отчётов: в `CHAPTER3_VALIDATION.md` — до 10 строк на часть
(оценки §8.3 с одной цитатой на пункт).

## Как писать с первого раза

* Одна часть = одно место за один участок, 250–400 строк, за одну сессию. Сначала план-таблица на 10–15 строк
  (2–3 события: время, люди, варианты, цена, где вспомнят исход; один момент опасности с `risky` или проверкой навыка).
* Каждый текст: человек (реплика/жест с характером) + конкретная деталь + короткая последняя фраза. Без мелочей
  «Проверить/Убрать/Положить», без тиков («больше не…», «сухой…»).
* Порог: ≥ 30 действий на участок у любопытного игрока, ≥ 2 события-прерывания, ≥ 2 экрана с риском — закладывать сразу,
  а не добирать после проверки.
