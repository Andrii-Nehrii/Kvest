# ЗАКРЫТО ДЛЯ ИГРОКОВ — как пишется новая глава (процесс, устройство, проверки)

Голос и стиль — `WRITING_GUIDE.md`. Законы мира — `WORLD_BIBLE.md`. Что уже случилось и какие флаги есть — `STORY_STATE.md`.
Образец устройства главы — `src/content/chapter2/` (повторять его приёмы, а не изобретать новые).

## 0. Порядок работы (строго по шагам)

1. **Прочитать:** `CLAUDE.md`/`AGENTS.md`, `docs/ARCHITECTURE.md` (§3–§10), `docs/hidden/*`, весь `src/content/chapter2/`,
   `src/content/chapter2.test.ts`. Сохранения пары (`git fetch origin saves:refs/remotes/origin/saves`, `pairs/<id>/save-A|B.json`):
   где они, что знают, что с NPC — чтобы самая вероятная их линия была самой проработанной.
2. **План — файлом** `docs/hidden/CHAPTER<N>_PLAN.md` до кода:
   * хронология дня: события мира (время, что меняют), планы NPC (время, условия), сроки болезней укушенных (WORLD_BIBLE);
   * **матрица стартов**: все места, где игрок может оказаться после прошлой КТ (по её `next` и сценам), вместе/порознь —
     и для каждого: какая сцена, что там делать, как дойти до следующей КТ;
   * участки (обычно 2 на игровой день: до ~середины дня и до ночи), их КТ: заметки при слиянии, совместное решение
     (варианты, объективная выполнимость, компромиссы, арбитры), `next`;
   * новые места, предметы, факты, NPC, флаги — со списком, кто их ставит и кто читает.
3. **Код** в `src/content/chapter<N>/` (как в главе 2): `world<N>.ts` (места, факты, NPC, планы NPC, события, радио, зоны),
   файлы сцен по участкам, `kt<N>.ts` (КТ и решения). Подключение — в `src/content/index.ts` (сцены, факты, события,
   `withAgenda`, `joint`, `checkpoints`). `next` прошлой КТ — на новые сцены (если её ещё никто не прошёл).
4. **Тесты** (§5), затем **самопроверка по чек-листу** (§6) — честно, по каждому пункту.
5. `npx tsc --noEmit && npx vitest run` — всё зелёное; затем `npm run e2e:quick` и сценарий `codes` на все КТ.
6. Коммит в свою ветку, PR в main **без слияния** (сливает владелец после проверки). Отчёт владельцу — без сюжета (§7).

  Тексты прошлых глав править можно (хэш мира не включает тексты), но лучше не трогать.
* Всё новое — за `{ cp: N }`: события мира, пункты планов NPC, поздние срабатывания старых планов (добавить `{ not: { cp: N } }`
  в старый пункт, если он не должен стрелять в новой главе — это не меняет прошлого), базы — `BaseDef.from`.
* `fixtures/release-N.json` не перегенерировать; `compat.test.ts` должен проходить. `content.version` не поднимать.
* Id прошлых сцен/переменных/предметов не переименовывать.

## 2. Устройство сцены (шпаргалка)

```ts
S({ id: 'c5_xxx', for: 'any', chapter: 'ch3', location: 'hof_luedemann', title: 'Короткий заголовок', safe: true,
  text: [{ when: AM, text: '…' }, { when: { all: [EVE, withPartnerAt('hof_luedemann')] }, text: '…' }],
  actions: [
    { id: 'c5_talk', label: 'Поговорить с Хенрике', minutes: 15, combinable: true, when: notDone('c5_talk'),
      text: '…', effects: once('c5_talk', [{ npc: 'henrike', trust: 4 }]) },
    { id: 'c5_go', label: 'Ночь. Устроиться на ночлег', minutes: 5, terminal: true, goto: 'c6_cp6', when: { all: [C5, after(20, 0)] } },
  ] })
```
* Id сцен и действий главы — со своим префиксом (`c5_…`), не пересекаться с прошлыми.
* Хаб-сцена места: тексты на каждое время суток (NIGHT / AM / PM / EVE) — нет «утренних» фраз днём; действия с окнами времени.
* `safe: true` — можно спать (универсальное «Лечь спать»); `calm` — бытовые правила без сна; `universal: false` — без
  «попить/поесть» (КТ-сцены, острые сцены). `ambient` — если игрок в машине/под крышей вне помещения.
* Переход к КТ — последним в списке; толчок-событие за час-два до конца участка (как `ev2_cp3_push`).
* Каждая хаб-сцена: есть «переждать час» (`waitHour`) и выход; нет тупиков (тест ловит 80–90 действий в одной сцене).

### Условия (`Cond`) — частые
`{ at }`, `{ partnerAt }` (партнёр в твоей линии стоит там, где был на КТ), `{ flag: '$.x' | 'w.x' | 'A.x' }`, `{ v, op, value }`,
`{ has }`, `{ hasTag }`, `{ npc, at, status, alive: true, trust: ['>=', n] }`, `{ npcVar, key, value? }`, `{ knows }`,
`{ before | after: at(day, h, m) }`, `{ me: 'A' | 'B' }`, `{ cp: N }`, `{ itemAt, place }`, `{ fuelFor, km }`, `{ fuelIn, liters }`,
`{ injured, minSeverity }`, `{ body: 'coreTemp', op, value }`, `{ stocked, qty, at }`, `{ callable: true }`, `{ partnerKnows }`.
**`{ npc, at }` не проверяет, жив ли NPC** — добавлять `alive: true`.

### Эффекты — частые
`set`, `add`, `give` (можно `fuel`), `take`, `takeTag`, `use: 'dressing'`, `pickup`/`drop`, `place`, `stock`/`unstock` (с `at`),
`body: { stress|fatigue|hunger|thirst, delta }`, `injure` / `biteArm(site, severity)` (риск через одежду), `treat`, `learn`, `move`,
`npc: { trust, remember, set, status, moveTo, alive }`, `wait`, `sleep`, `drive`/`driveTo(km, to, jam)`, `refuel`, `fillCan`, `siphon`,
`work` (проекты), `if/then/else`. Поездка: **сначала игрок у машины** (`toCar`), потом `drive` с `to` — `move` после; при нехватке
бензина `drive` не переносит — всегда есть запасной путь пешком.

### События и планы NPC
* `events`: `scope: 'world'` — у обеих линий, эффекты **только `set`** (линтер); личные — `scope: 'A'|'B'`. `interrupt` — будит,
  прерывает план. `news` — по каналу (direct/radio/phone/people); **в тексте новостей без шаблонов**. Окна `before`, иначе
  событие сработает с опозданием у того, кто пришёл позже.
* Что должно случиться без игрока (NPC укусили, уехал, обратился) — **пункт плана NPC** (`agenda`, `withAgenda` в index.ts),
  а не событие у игрока. События — только чтобы игрок это увидел/услышал.

## 3. Два телефона (самое важное)

* Каждый участок каждый играет на своём телефоне; на КТ линии сливаются (`mergeSegments`): своё тело/знания — из своей линии,
  мир — «изменил один → его значение, оба → позднее», количества и топливо — сумма изменений.
* **Вместе в одном месте** (`w.together` + одно место):
  * машиной и бензином распоряжается **только линия A** (у B — просто `move`); расход ресурсов — у одной линии;
  * судьбу NPC в «своём» доме решает хозяин места (`{ me }`), гость — помогает/говорит;
  * далеко не уходить и не менять маршрут — куда идти, решается на КТ; развилки общей дороги — **только объективные**
    (время, бензин, флаги проверки с КТ), а выбор каждого меняет его самого (тело, вещи, отношения);
  * исход, который должен быть одинаковым у обоих, — вычислить на КТ (заметка `onMerge` или эффект решения) и читать флагом.
* **Порознь**: каждый может идти к другому; приход к двери — сразу на КТ (`$.at_partner_door…`), встреча решается заметкой КТ.
* Заметки КТ применяются **сначала к A, потом к B на общем состоянии**: если эффект заметки меняет флаг, которым проверяется
  заметка B, — ставить личный флаг (`$.ktN_found`) и проверять партнёра через `@partner.`.
* Решение на КТ: выполнимость (`feasible`) — объективная, от лица мира (ctx A: `at` — где A, `partnerAt` — где B); порознь
  разные ответы → компромисс «остаёмся»; вчерашний план побеждает в споре только вместе; `default` — выполнимый вариант.

## 4. Темп и объём

* Участок: ~35–50 минут игры на игрока, 50–70 решений; в начале — 2–3 сильные ситуации, дальше — жизнь места.
* Каждое место, где игрок может провести участок, — полноценное: 8–15 действий, вечерние события, люди.
* Главная вероятная линия пары (по сохранениям) — самая богатая; редкие — короче, но без тупиков.

## 5. Тесты новой главы

* `src/content/chapter<N>.test.ts` по образцу `chapter2.test.ts`: построить состояние после прошлой КТ для **каждой строки
  матрицы стартов** (вместе/порознь, разные места, машина/без), сыграть участки случайными, но разумными игроками до КТ,
  слить, ответить на решение (случайно и заданными ответами на каждый вариант), проверить: дошли до следующей сцены, нет
  тупиков, нет неподставленных шаблонов, журнал воспроизводится бит в бит. Плюс регрессии на каждую найденную ошибку.
* `story.test.ts` — добавить участки новой главы в цикл (30 пар через все КТ); `lines.test.ts` — главная линия.
* `scripts/e2e/codes.cjs` — цикл по всем КТ.
* `style.test.ts` — механика текстов (род, шаблоны, подписи) — должен проходить.

## 6. Чек-лист самопроверки (ошибки, которые реально находили при проверках)

- [ ] Мёртвый NPC «стоит» на месте и с ним можно взаимодействовать (`alive: true` в условиях).
- [ ] Поездка: игрок не у машины → `drive` не работает; `move` до `drive` бросает машину; нехватка бензина → тупик без пешего пути.
- [ ] Один игрок попадает в чужую квартиру без ключей / без хозяина.
- [ ] Текст обещает действие, которого нет («можешь ехать дальше один»).
- [ ] Утренний текст днём, «темнеет» вечером, «мокрый» после дождя, «она засыпает» днём — окна времени у текстов и действий.
- [ ] Событие должно случиться без игрока — сделано событием у игрока (не срабатывает, если его нет рядом).
- [ ] Последствие наступает, когда игрок уже вмешался (проверять сцену/флаг вмешательства).
- [ ] Одно и то же решение принимают обе линии (судьба NPC, расход бензина, отъезд) — оставить одной линии.
- [ ] Заметки КТ: второй игрок не видит встречи/новостей из-за порядка применения.
- [ ] Решение КТ: порознь при разных ответах выигрывает «вчерашний план» вместо «остаёмся»; «туда же» невыполнимо для тех, кто уже там.
- [ ] Персонаж знает то, чего не узнавал (имена, детали чужой линии).
- [ ] Род: «ты видела» в общей сцене, `{pm:смотрит|смотрит}`; шаблоны в новостях событий.
- [ ] Каждая хаб-сцена: выход есть в любое время; переход к КТ доступен; нет 80+ действий без смысла.
- [ ] Всё новое за `{ cp: N }`; `compat.test.ts` зелёный; сохранение пары из облака повторяется (`refreshSave` без обрезки).
