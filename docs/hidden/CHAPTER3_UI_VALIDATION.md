# Закрыто для игроков — совместимость интерфейса контрольных точек

Исправления `shouldSendAnswers` и `lastCheckpoint` нужны. Если один участник не может отвечать, его телефон должен получить подписанный ответ второго; иначе один телефон завершает точку, а второй остаётся ждать. Если после завершения недееспособный игрок сразу попадает на следующую точку, её объект `cp` вытесняет результат и коды предыдущей. Архив сохраняет только индекс, результат и отправленные коды — не вторую копию мира.

Граница включения — КТ5. `finishCheckpoint` при КТ1–4 не добавляет поле `lastCheckpoint` даже со значением undefined; `shouldSendAnswers` сохраняет старый порядок. Интерфейс читает архив только при индексе >=5. Форма существующих пакетов, schema:1, версия движка и контента не менялись.

Отдельная регрессия `src/app/chapter-checkpoint.test.ts`: все КТ1–4 сохраняют прежний набор полей; каждая КТ5–8 проходит обмен с одним отвечающим, даёт один хэш на обоих телефонах, сохраняет отправленный код. Последняя точка не превращается в несуществующую девятую. Дополнительная защита чтения архива в интерфейсе и эти тесты выделены отдельным коммитом. Исходное исправление уже содержится в предыдущем опубликованном коммите ветки; история PR не переписывается.
